API connection (AIS Server)

Instead of files: AP Coder signs in to your AIS Server as its own JDE user and calls the orchestrations your JDE team builds from docs/JDE_ORCHESTRATIONS.md. Step 1 reads suppliers, GL accounts, business units, open POs and the AP ledger's vouchers (every night, or now) and asks JD Edwards whether an invoice is already there while it is reviewed. Step 2 posts approved vouchers from Exports, after a dry run and an Approver's go-ahead; the batch files stay the fallback. Off, AP Coder connects to nothing; on, only to the AIS address below.

Province → tax area and explanation code

The tax area names are placeholders: use your E1 tax areas (F4008). Codes: V = GST/HST/QST recoverable, C = GST + seller-charged PST (PST in the distribution), B = self-assessed PST, E = exempt. Invoices with no tax charged use the exempt code; PST provinces without PST charged use the self-assessed code when every line owes the PST. {% if js.amount_mode == "gl" %}Not used while the tax is coded to G/L accounts (Amounts, above): each voucher goes with code {{ js.gl_tax_code }} and no tax area.{% endif %}

Payment terms → JD Edwards code

The code JD Edwards gets in VLPTC for the terms printed on an invoice. Terms are matched by what they mean: “Net 30”, “30 days” and “N30” are one row. Type the terms as on an invoice and your JD Edwards payment terms code (P0014, up to 3 characters). A row with no terms or no code is removed when you save. With no rows, JD Edwards uses each supplier's own terms.
