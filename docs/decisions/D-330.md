- **D-330** · **A pull request runs the whole suite on Windows 3.12 too, and CI's runs are grouped by their kind as
  well as their ref** (amends D-260; `.github/ci-tests.json`, the `concurrency` of `.github/workflows/ci.yml`;
  20 Nov 2026).
  - **Why:** 3 of the 12 merges of 20 Nov (pull requests 153, 157 and 158) failed on main only, on Windows with
    Python 3.11 or 3.12: a read-only file Windows would not remove before Python 3.13 (B-2725), its clock in 1/64 s
    steps before 3.13 (B-2997), and the import queue's tests of several processes ("database is locked"). A pull
    request's Windows 3.14 cell can't show what Python 3.13 changed on Windows, so each was found after the merge,
    as a red main and another pull request. Separately, a merge, the nightly and a run by hand all run on main's ref,
    so the group `ci-${{ github.ref }}` (the older run cancelled) made them cancel each other: the nightly run 757
    was cancelled 21 s after a merge's run was run again, and a merge's run the nightly cancels gives its commit no
    tested build (`builds.yml` releases a merge's passed run).
  - **How:** the 4 Windows 3.12 parts of the whole suite (with OCR) are marked `"pull_request"`, so the `plan` job
    picks them for a pull request: 28 jobs run instead of 24, the others as before; main and the nightly run the same
    50. Worked out from 20 Nov's job times (20 jobs at a time): about 2 minutes more of a pull request's wall time
    (21.1 to 23.2), against 38 to 44 minutes for the full run by hand used before merging. The group is
    `ci-${{ github.event_name }}-${{ github.ref }}`: a pull request's next push and the next merge still cancel the
    older run of their kind; the nightly, a run by hand and a merge never cancel each other (they may now run side by
    side, sharing the 20 job slots). `tests/core/test_imports.py` says why a child Python failed, so that flake names
    itself on a pull request. Tested by `tests/meta/test_ci_workflow.py`
    `::test_a_pull_request_runs_the_suite_on_ubuntu_and_the_pilot_laptops_windows_and_main_runs_everything` and
    `::test_the_nightly_a_run_by_hand_and_a_merge_never_cancel_each_other`.
  - *Not chosen:* Windows 3.12 instead of 3.14 (3.14 is the pilot laptop's Python, B-2105, and caught B-2653 on a
    pull request); a Windows 3.11 cell (ruff's py311 target refuses newer syntax already, and what Python 3.13
    changed on Windows is the same on 3.11 as on 3.12: B-2725 failed on both); the Windows 3.12 fast tier (about the
    same wall time, but it leaves out the slow tests of several processes); only the changed tests on Windows (92 to
    159 test files a pull request, or all of them); a full run by hand before each merge (38 to 44 minutes, and it
    slowed the pull request beside it); failed tests run again until they pass.
