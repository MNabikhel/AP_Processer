- **D-328** · **From B-2998 and D-328 on, each bug and each decision is a file of its own, numbered when it is written
  (`scripts/new_entry.py`); docs/BUGS.md and docs/decisions.md are frozen at B-2997 and D-327** (D-125, D-325).
  - **Why:** two branches that each added an entry added to the end of one file, so they conflicted there: BUGS.md was
    in all 33 conflicted merges of one night (115 of 137 since 29 October), decisions.md in 19, and 27 of the 33 had
    no other conflict. `scripts/combine.py` settled them only when it was run (4 of that night's 53 merges): a plain
    `git merge`, a rebase or GitHub's Update branch still stopped. Numbers handed out to helpers in blocks left 46% of
    them unused, and the newest-number test failed 31 of that night's 281 commits, 22 times because the last line
    named an older number in its words.
  - **How:** a bug is `docs/bugs/B-NNNN.md`, its one line as in BUGS.md; a decision is `docs/decisions/D-NNN.md`, the
    entry and its lines as at the end of decisions.md. Two branches add two files, which git merges.
    `python scripts/new_entry.py B|D "text"` (a decision's lines with `--file`, or on stdin) takes one more than the
    highest number an entry has: in the checkout (the frozen logs, the archive, the folders), on every local and
    remote branch (two `git cat-file` passes, under a second; nothing fetched) and among the numbers reserved. It
    reserves it by making `<git common dir>/ap-numbers/B-NNNN` only if it is not there (O_EXCL; the worktrees of a
    clone share that folder), writes the file, adds it to git and prints the number for the test and the commit.
    Separate clones can still take one number: combine.py gives the later branch's file the next one, the file
    renamed and its mentions in the lines that branch changed with it, and moves an entry a branch made before the
    cut-over added to a frozen log into its file. `tests/meta/test_log_entries.py`: a file holds the one entry it is
    named after, no number has two entries, the frozen logs end at B-2997 and D-327, every number the code names has
    an entry (B-0, B-989 and B-2187 aside), and `grep -rnw "B-1234" docs/BUGS.md docs/bugs docs/archive` (the
    lookup the docs give; the old one found no entry, 0 of 1,911) finds an archived, a frozen and a new one.
  - *Not chosen:* the 1,311 entries moved into files (nothing to gain at a merge, as no old entry is edited, and some
    1,300 files more in the offline ZIP); an index generated and committed (its end conflicts again at each merge);
    numbers given at the merge (213 of that night's 228 commit subjects, and the tests, name the number written);
    `merge=union` (it keeps a line twice when one side edits it and the other adds after it); WHATS_NEW.md changed
    too (no conflict in 315 merges, and the help page shows it); number blocks by hand (46% unused, and a lower block
    merged after a higher one failed the newest-number test); a rule against gaps (a number reserved for a branch
    never merged is one, by design) or for the newest number last (the script gives it).
