- **D-338** · **Reviews run as the `reviewer` agent (`.claude/agents/reviewer.md`)** (D-106; 27 Nov 2026).
  - **Why:** the review steps of the past weeks' work were each given the same checklist by hand, a little different
    every time, and what they caught was of a few kinds again and again: a renamed name still used by a template, a
    test or a doc; what an older build does during an update or after a rollback; Windows' file locks and encodings;
    a new test that passed on the parent too; a claim of no change in behaviour left unproven. Written once, every
    review gets all of it, with D-106's small tool set and short prompt.
  - **How:** `.claude/agents/reviewer.md`: the developer's tools (Bash, Read, Edit, Write, WebFetch, WebSearch); assume
    the change wrong until shown otherwise, read the whole diff, see each new test fail on the parent and pass on the
    commit, and the rest of the checklist; fix a defect test-first in the branch's worktree or revert what it can't
    make safe; a verdict per commit (keep, fixed, reverted). `tests/meta/test_agent_profile.py` holds every profile
    in `.claude/agents/` to its name, its tools and the scripts it names. CLAUDE.md names it (`subagent_type:
    "reviewer"`) with `scripts/release_proof.py`, a release's real update test.
  - *Not chosen:* the checklist in the developer profile (every coding task would carry it); more tools for the
    reviewer (`gh` through Bash reads pull requests, releases and CI logs).
