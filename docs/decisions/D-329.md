- **D-329** · **`scripts/check.py` always runs the rules that check the whole tree, runs a changed doc's rules, and
  never says OK when a changed module of the app ran no test.**
  - **Why:** two of the late CI failures of 20 November (the KEPT list of `tests/meta/test_core_imports.py` at 6420278,
    the offline guard's TOUCHPOINTS at b4c06bf) fail in under 3 s on their own tree, yet the check picked neither: no
    test is named after the file changed or imports it. Each cost a CI round of 20 to 60 minutes. 26 modules of the app
    (11,783 lines: `ai/offline_coder.py`, the review screen's routes...) got no test at all while the check said OK, and
    a store part's tests were looked for from the folder it ran in: none from another one.
  - **How:** `RULES` (all of tests/meta with its slow tests but no browser, the offline guard's quick tests,
    `test_store_package`, `test_help`, `test_roles`, `test_role_permissions`) run in a pytest run of their own
    (`rules_args`) whenever a file of the app or the scripts, or a Python file of the tests, is changed, added, deleted
    or moved: about 27 s serially on a quiet machine. A changed doc runs `DOC_RULES` (`test_agent_friendly`, and
    `test_log_entries` once it is there) and the tests that open it by its path; QUICK_START.md and WHATS_NEW.md the
    Help page's too. A module more than `WIDE` test files import brings the quickest of them, its own tests folder
    first, up to `BUDGET` (20 s by tests/test_times.json) instead of none; `OWN` names the tests of the files named
    otherwise. A changed module of the app still with none prints `NO TESTS RAN FOR` and fails the check. A changed
    function of 110 lines or more, or a store part of 950, gets a warning to split it first. On the two cause commits'
    trees the new check fails on the rule CI caught; picking tests by the function changed (B-2950, B-2970) comes next.
  - *Not chosen:* the import closure (265 to 286 of 378 test files: the whole suite in disguise); a higher `WIDE`; all
    of tests/offline (the bundle and network-namespace walks take over 100 s); a note and exit 0 for a module with no
    tests (the false OK the audit found).
