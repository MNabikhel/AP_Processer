- **D-329** · **`scripts/check.py` always runs the rules that check the whole tree, runs a changed doc's rules, picks
  the tests that name a changed function, runs long runs on several cores, and never says OK when a changed module of
  the app ran no test.**
  - **Why:** two of the late CI failures of 20 November (the KEPT list of `tests/meta/test_core_imports.py` at 6420278,
    the offline guard's TOUCHPOINTS at b4c06bf) fail in under 3 s on their own tree, yet the check picked neither: no
    test is named after the file changed or imports it. Two more (B-2950 at 22082a4, B-2970 at 701e2fd) were caught by
    tests that name the function changed but import a module too many tests use. Each cost a CI round of 20 to 60
    minutes. 26 modules of the app (11,783 lines: `ai/offline_coder.py`, the review screen's routes...) got no test at
    all while the check said OK, and a store part's tests were looked for from the folder it ran in: none from another
    one.
  - **How:** `RULES` (all of tests/meta with its slow tests but no browser, the offline guard's quick tests,
    `test_store_package`, `test_help`, `test_roles`, `test_role_permissions`, and the one test of `test_migrations` that
    each schema since 27 has an old database: B-2999, a schema raised in `_base.py` alone ran none of it) run in a
    pytest run of their own (`rules_args`) whenever a file of the app or the scripts, or a Python file of the tests, is
    changed, added, deleted or moved. A changed doc runs `DOC_RULES` (`test_agent_friendly`, and `test_log_entries` once
    it is there) and the tests that open it by its path; QUICK_START.md and WHATS_NEW.md the Help page's too. A module
    more than `WIDE` test files import brings the quickest of them, its own tests folder first, up to `BUDGET` (20 s by
    tests/test_times.json) instead of none, and says what it left to CI; `OWN` names the tests of the files named
    otherwise. The functions whose lines the diff touches (`git diff -U0`, the file as it is and, for lines taken out,
    as it was) bring the test files that name one as a whole word, a name more than `WIDE` of them have aside. The files
    picked run with their slow tests but no browser (`--fast`: without). A run estimated over 15 s goes on `-n` workers
    (pytest-xdist 3.8.0, the `parallel` extra; `AP_CHECK_WORKERS`, `--serial`): the rules 30 s serially, 18 s on 4, and
    tests/coding, core and erp gave the same pass sets both ways. A changed module of the app still with none prints `NO
    TESTS RAN FOR` and fails the check; a changed function of 110 lines or more, or a store part of 950, gets a warning
    to split it first. On the four cause commits' trees the new check fails on the test CI failed on.
    `OLD_WINDOWS_CLOCK` turns tests/conftest.py's coarse clock on, once it passes as CI does.
  - *Not chosen:* the import closure (265 to 286 of 378 test files: the whole suite in disguise); a higher `WIDE`; all
    of tests/offline (the bundle and network-namespace walks take over 100 s); a note and exit 0 for a module with no
    tests (the false OK the audit found); pytest-xdist in `dev` (the offline bundle carries `dev`: its wheelhouse would
    change); a coverage map on every run (it slows each run and is kept per computer).
